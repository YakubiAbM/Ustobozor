## Деплой Ustomarket на Timeweb (VPS / Cloud Server)

Ниже — минимальная инструкция, рассчитанная на **VPS/Cloud-сервер с Docker** на Timeweb.
Если на аккаунте есть только "Docker-контейнер" без docker-compose, используйте просто `Dockerfile` из проекта — образ будет собран по тем же шагам.

### 1. Подготовка сервера

- Создайте сервер с **Ubuntu 22.04+**.
- Зайдите по SSH и установите Docker и Compose (официальная инструкция Docker).
- Откройте порт `8000` в правилах фаервола Timeweb (или настройте Nginx/балансировщик на 80/443 поверх него).

### 2. Клонирование проекта

```bash
git clone <ВАШ_REPO_URL> ustomarket
cd ustomarket
```

Скопируйте файл `.env` с рабочего окружения (локальной машины) на сервер в корень проекта и при необходимости поправьте:

- `DATABASE_URL` — если используете **внешний PostgreSQL Timeweb**, укажите его DSN.
- Если используете Postgres в Docker (см. compose ниже), `DATABASE_URL` в `.env` можно игнорировать — в контейнере оно переопределяется.

### 3. Вариант A: Docker Compose (app + Postgres в контейнере)

В проект добавлен файл `docker-compose.yml` со службами:

- `app` — FastAPI (`uvicorn main:app --host 0.0.0.0 --port 8000`), порт проброшен на `8000` хоста;
- `db` — Postgres 16 c базой `market` и пользователем `postgres/7900`;
- `DATABASE_URL` для `app` внутри compose уже указывает на `db:5432`.

Запуск:

```bash
docker compose pull        # на случай, если уже есть образы
docker compose build       # собрать образ приложения
docker compose up -d       # поднять app + db в фоне
```

После этого API и PWA будут доступны по:

- `http://<SERVER_IP>:8000/web/` — PWA Ustomarket;
- корневые эндпоинты API (`/products`, `/masters`, `/orders`, `/auth/...`) — на том же хосте/порту.

> Если нужен HTTPS и домен — поверх этого можно поставить Nginx + Let’s Encrypt, который будет проксировать 80/443 на `app:8000`.

### 4. Вариант B: только приложение в Docker, Postgres — управляемый сервис Timeweb

1. В Timeweb создайте управляемую базу PostgreSQL и получите строку подключения `DATABASE_URL`.
2. Пропишите её в `.env` на сервере.
3. Удалите (или закомментируйте) сервис `db` и секцию `volumes` в `docker-compose.yml`, а также строку `DATABASE_URL=...` в `environment` у `app`, чтобы использовалось значение из `.env`.
4. Запустите только `app`:

```bash
docker compose up -d --build app
```

### 5. Запуск как одного Docker-контейнера (Timeweb Docker)

Если платформа Timeweb позволяет указать **только Dockerfile**:

1. Укажите в настройках сборки путь к `Dockerfile` в корне проекта.
2. В переменных окружения Timeweb задайте:
   - `DATABASE_URL` — строка подключения к вашей БД,
   - при необходимости `PORT` (если платформа ожидает другой порт; по умолчанию контейнер слушает `8000`).
3. Соберите и запустите контейнер. Приложение будет доступно по порту/домену, который выдаёт Timeweb, а PWA — по пути `/web/`.

### 6. Обновление версии

На сервере:

```bash
cd ustomarket
git pull
docker compose up -d --build
```

Docker пересоберёт образ и перезапустит контейнер с новой версией бэкенда и PWA.
